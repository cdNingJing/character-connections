# 规则布局与曲线路由

## 默认规则

规则布局不使用随机数，也不按数据数组顺序安排人物。

1. `coreId` 指定核心人物，放在 `(0, 0)`。未指定时按关联关系数量降序选择，相同数量按 id 升序决定。
2. `placement.level` 表示垂直层级，负数在上，0 为核心同层，正数在下。
3. `placement.order` 表示左右顺序，负数在左，正数在右。
4. 默认横向间距 210，纵向间距 190。相同槽位按 id 确定性地向邻近空位分配，不叠放节点。
5. 未提供 placement 时，核心的师承关系默认上层、冲突默认下层，其余默认同层。需要准确的业务布局时应显式提供 placement。
6. 已导入的 `position` 或用户手动调整位置优先；点击“重新排列人物”后按规则恢复。

示例：

```json
{
  "coreId": "wukong",
  "characters": [
    {
      "id": "wukong",
      "name": "孙悟空",
      "group": "取经团队",
      "placement": { "level": 0, "order": 0 }
    },
    {
      "id": "tangseng",
      "name": "唐僧",
      "group": "取经团队",
      "placement": { "level": 0, "order": -1 }
    },
    {
      "id": "guanyin",
      "name": "观音菩萨",
      "group": "神佛与仙人",
      "placement": { "level": -1, "order": -1 }
    }
  ]
}
```

上面的片段只展示布局字段；完整 JSON 仍需 schemaVersion、title、relations 等字段。

《西游记》的位置是为解释人物关系而作的可视化编排，不表示原著中的地理方位、身份等级或全部人物重要性。

## 演变过程

演示先用完整的 26 人物数据计算位置，再按阶段增量加入人物与关系：

- 第 1 阶段：孙悟空，1 人物、0 关系。
- 第 2 阶段：取经团队，5 人物、7 关系。
- 第 3 阶段：神佛与天庭，13 人物、17 关系。
- 第 4 阶段：完整示例，26 人物、43 关系。

`updateDataPreservingPositions()` 保留已有节点实例和坐标，只添加新节点、新关系，或移除退回阶段不再包含的内容。选中人物只改变样式；视图缩放始终以核心人物为中心。

演示阶段表示关系图复杂度，不是原著时间顺序。部分连线表示同一人物对在不同故事阶段的关系，例如玉帝对孙悟空的招安与征讨，不能解读为同时发生。

## 连线路由

默认曲线使用 Cytoscape.js 的 `unbundled-bezier`，为每条关系单独计算控制点：

- 按关系 id 固定处理顺序。
- 将正向、反向关系视为同一人物对，为平行关系分配不同曲率，避免完全重合。
- 在一组确定的正负曲率候选中采样曲线，优先选择不穿过其他人物节点的路径，再选择较短的弯曲路径。
- 关系文字向远离核心的方向偏移，减少中心文字堆积。
- 拖动人物或重新布局后重新计算路径。

“避免重合”不等于“任意复杂图都能无交叉”。非平面关系网不能保证全部边都不相交；当前路由也不保证任意手动坐标下都能避开所有节点。启用直线或折线属于主动选择，可能重新出现重叠。第一版没有全局交叉最小化求解器。

## 扩展

分组、环形布局仍可主动选择；力导向仅保留源码 API 兼容，不作为默认演示选项。未来可增加按关系类型的指定连接点、标签避让和多层折叠。

手机查看全图时，缩放比例较小会隐藏密集文字，保留核心人物名称；放大后显示人物与关系文字，避免全部标签挤在一起。简单曲线无法避让时会尝试多控制点路径。
